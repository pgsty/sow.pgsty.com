01 · {{ if $zh }}双引擎{{ else }}TWO ENGINES{{ end }}

{{ if $zh }}平面与托管，两种模式{{ else }}Plain or Managed{{ end }}

◇ {{ if $zh }}一条命令起步，一套模型长跑{{ else }}One command to start. One model to grow into{{ end }}

  • {{ if $zh }}Plain：sow create 就地索引一个放着 rpm / deb 的目录{{ else }}Plain: sow create indexes a directory of rpm / deb files in place{{ end }}
  • {{ if $zh }}Managed：工作区 → 仓库 → Dist 三层模型，包池与发布视图分离{{ else }}Managed: workspace → repository → dist, with the pool separated from published views{{ end }}
  • {{ if $zh }}两条路径互不干扰；Plain 输出确定，Managed 变更可审计、可校验{{ else }}The paths never mix: Plain is deterministic; Managed changes are audited and verified{{ end }}

{{ if $zh }}从临时目录到长期维护的软件源，不必换工具{{ else }}From a scratch directory to a long-lived feed, without changing tools{{ end }}

quickstart.sh 
# Plain: index a directory as it is
sow create /srv/repo

# Managed: a workspace you keep
sow init /srv/sow
cd /srv/sow
sow repo new pigsty
sow dist new el9 --format rpm
sow add /path/to/packages/*.rpm -d el9

02 · {{ if $zh }}包池与视图{{ else }}POOL AND VIEWS{{ end }}

{{ if $zh }}一份包体，多个视图{{ else }}One Payload, Many Views{{ end }}

↔ {{ if $zh }}包池持有内容，视图只是投影{{ else }}The pool owns the bytes. Views are projections{{ end }}

  • {{ if $zh }}Debian 风格 pool/ 包池，内容不可变、按首字母分组{{ else }}A Debian-style pool/ holds immutable payloads, grouped by initial{{ end }}
  • {{ if $zh }}架构视图只含元数据，包体只存在规范包池{{ else }}Architecture views contain metadata only; payloads stay in the canonical pool{{ end }}
  • {{ if $zh }}noarch / all 作为中性包进入每个适用视图{{ else }}noarch / all packages land in every applicable view{{ end }}

{{ if $zh }}每个 Repository 只由规范包池持有一份包体，元数据视图不再复制{{ else }}Within each Repository, the canonical pool owns one payload copy; metadata views add none{{ end }}

04 · {{ if $zh }}事务与审计{{ else }}TRANSACTIONS AND AUDIT{{ end }}

{{ if $zh }}中断不破坏仓库{{ else }}Crash-Safe by Design{{ end }}

＋ {{ if $zh }}先记意图，再动文件{{ else }}Record the intent, then touch the files{{ end }}

  • {{ if $zh }}写操作先落 journal，崩溃后由下一条写命令前滚或回滚{{ else }}Writes are journaled first; the next write command rolls them forward or back{{ end }}
  • {{ if $zh }}提交顺序固定：包体 → 元数据 → 指针 → 删除，客户端看不到撕裂状态{{ else }}Commit order is fixed—payload, metadata, pointer, delete—so clients never see a torn tree{{ end }}
  • {{ if $zh }}操作账本可查、可导出 JSONL：sow log / sow log export{{ else }}The operation journal is queryable and exportable: sow log, sow log export{{ end }}

{{ if $zh }}证据不足就拒绝执行，而不是猜一个结果{{ else }}When the evidence is insufficient, it refuses—rather than guessing{{ end }}

SCOPE

{{ if $zh }}专注，源于取舍{{ else }}Focused by Design{{ end }}

{{ if $zh }}SOW 构建并发布静态仓库树；右侧列的是明确非目标，不是待办清单。{{ else }}SOW builds and publishes static repository trees. The right column lists intentional non-goals, not a backlog.{{ end }}

{{ if $zh }}覆盖范围{{ else }}IN SCOPE{{ end }}

{{ if $zh }}SOW 负责的部分{{ else }}What SOW does{{ end }}

  • {{ if $zh }}RPM 与 DEB 仓库索引的生成与维护{{ else }}Generating and maintaining RPM and DEB repository indexes{{ end }}
  • {{ if $zh }}包池、架构视图与成员策略{{ else }}Package pools, architecture views, and membership policy{{ end }}
  • {{ if $zh }}元数据签名与 RPM 包签名{{ else }}Metadata signing and RPM package signing{{ end }}
  • {{ if $zh }}事务、审计，以及向 filesystem / R2 发布{{ else }}Transactions, audit, and publication to filesystem or R2 targets{{ end }}

{{ if $zh }}明确非目标{{ else }}EXPLICIT NON-GOALS{{ end }}

{{ if $zh }}SOW 不做的部分{{ else }}What SOW does not do{{ end }}

  • {{ if $zh }}造包：SOW 索引软件包，不构建软件包{{ else }}Building packages—SOW indexes them, it does not produce them{{ end }}
  • {{ if $zh }}充当 HTTP 服务或 CDN：SOW 发布静态树，但不负责在线分发{{ else }}Acting as an HTTP server or CDN—SOW publishes static trees but does not serve them{{ end }}
  • {{ if $zh }}多机多写：单写者模型，不做分布式协调{{ else }}Multi-writer setups—the model is single-writer by design{{ end }}
  • {{ if $zh }}modulemd、sqlite repodata、zchunk 与源码包索引{{ else }}modulemd, sqlite repodata, zchunk, and source package indexes{{ end }}
